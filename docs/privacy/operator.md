- What the operator sees when the public preview shows live Farcaster posts: those reads go through the preview's own server, so the operator sees the address, the time and which thread or profile was read (the discovery timeline names nothing: it is the posts of the authors the operator chose, as a list or as the accounts a "house" Farcaster account follows, identical for every visitor; channels are not relayed). If the operator curates through a house account, its follow list, and so exactly whose posts the preview shows, is public on Farcaster, and whoever controls that account decides what the discovery timeline shows. The hosting platform sees it too, without the app's help: opening a live profile or thread is a page request for `/<fname>` or `/<fname>/status/<hash>`, and the platform's HTTP log records that path next to the address for every one a visitor opens. Because the same operator runs the validator, those reads can be matched to a root's traffic by address and time. The relay's cache is shared, so another visitor can tell from an answer's speed that someone opened the same profile or thread recently (never who). The read key stays on the server, the visitor's own fid is never sent, and Following, notifications, history and search are not relayed. {cite: SECURITY-POSTURE.md > "19.
