# ZK Pass 1: Foundation + First Private Gate

> Written from `notes/reports/REPORT-Z1.md`. Every claim below cites the report section it comes from.

## What shipped

- **[SHIPPED]** Gate 0: a Semaphore v4 identity/nullifier foundation — a per-root Semaphore identity derived via an HKDF branch, the nullifier formula matching the audited circuit exactly, a frozen and versioned scope registry, and signed device-auth registration on the validator. {cite: notes/reports/REPORT-Z1.md > "GATE 0 — BUILT + CLOSED. accept-z0 11/11 (first run, ARMED)"}
- **[SHIPPED]** Ceremony-artifact verification: the shipped Semaphore v4.13.0 keys were traced to the "Semaphore Binary Merkle Root Fix" ceremony (finalized 2025-07-23, after the OtterSec under-constrained-circuit report), with hashes matching byte-for-byte against the ceremony's own published outputs and a third party's public attestation. {cite: notes/reports/REPORT-Z1.md > "The finding that reshaped Gate 0 before it started"}
- **[SHIPPED]** Public per-(mode, epoch) Merkle trees on the validator (`valid`, `tier-1..10`, `attest:<issuer>` scaffolded) with signed placements and a signed, hash-chained, append-only root history that the client TOFU-pins and anchors in its vault. {cite: notes/reports/REPORT-Z1.md > "GATE 0 — BUILT + CLOSED. accept-z0 11/11 (first run, ARMED)"}
- **[SHIPPED]** A live prover (stock Semaphore in an isolated worker) producing real Groth16 proofs, with artifacts re-hashed against build pins on every load and the proof self-verified before it leaves the process. {cite: notes/reports/REPORT-Z1.md > "GATE 0 — BUILT + CLOSED. accept-z0 11/11 (first run, ARMED)"}
- **[SHIPPED]** Gate 1: an anonymous submission channel (`POST /zk/anon/submit`) with an allowlisted header set, stateless hashcash proof-of-work rate limiting, constant-shape/constant-time responses, and an OHTTP (RFC 9458) relay path so the validator only ever sees a gateway, not a submitter's identity. {cite: notes/reports/REPORT-Z1.md > "GATE 1 — The anonymous submission channel (F1, the blocker) — BUILT"}
- **[SHIPPED]** Gate 2: For You discovery gated on a proven reputation tier (`ADAPTER_REP=zk`) rather than a persona's root-linked reputation — proof-mediated eligibility, with a frozen-epoch invariant so a rebuilt tree can never diverge from its signed history root. {cite: notes/reports/REPORT-Z1.md > "GATE 2 — The tier-threshold membership gate on For You — BUILT"}
- **[SHIPPED]** Gate 3: a computed, eight-condition privacy label (`PrivacyLabel.tsx` / `SECURITY-POSTURE.md`) that renders the exact narrow claim only when every condition holds in-process, and otherwise a named "DEMO — not yet private" state. {cite: notes/reports/REPORT-Z1.md > "GATE 3 — The computed privacy label + SECURITY-POSTURE.md — BUILT"}
- **[SHIPPED]** Gate 4: an operator-view linkage test plus three fresh-context adversarial reviews, with every one of 34 findings across the reviews fixed in this pass or recorded as a named assumption in SECURITY-POSTURE.md. {cite: notes/reports/REPORT-Z1.md > "GATE 4 — Operator-view linkage test + adversarial review — BUILT"}
- **[SHIPPED-FIXTURE]** The four consecutive closing sweeps (348 checks each) that closed the pass ran fixture-only transport, never proving live; the one live end-to-end proof (`live:z2`) ran once, separately, and is explicitly "never in sweeps." {cite: notes/reports/REPORT-Z1.md > "VERIFICATION — the fix iteration, on the rebuilt armed bundle"}
- **[KNOWN-BROKEN]** The call option — revocation via epoch re-issuance — was not exercised in this pass; recorded as A-REVOCATION-NOT-BUILT. {cite: notes/reports/REPORT-Z1.md > "Closure, stated exactly"}
- **[SPECCED]** Fork continuity, root-blind persona registration, and ending the validator's plaintext persona→root link are scoped as "Step 2" work this pass hands off but does not build. {cite: notes/reports/REPORT-Z1.md > "WHAT THE NEXT STEPS NEED — written from what this pass actually built"}

## What it found

- A trap the research prompt did not name: Semaphore's `toBigInt()` throws on any non-numeric string over 31 characters, so application scope strings (60+ chars) had to be hashed to a field element first rather than passed as raw bytes. {cite: notes/reports/REPORT-Z1.md > "GATE 0 — BUILT + CLOSED. accept-z0 11/11 (first run, ARMED)"}
- Running the live prover under `next start` crashed with "Worker is not a constructor" — snarkjs's thread pool, built through the `web-worker` polyfill, mistakes itself for its own child inside a `worker_threads` worker; fixed by making the prover a forked child process instead. {cite: notes/reports/REPORT-Z1.md > "VERIFICATION — the fix iteration, on the rebuilt armed bundle"}
- The rebuttal's worst finding for this layer's stated purpose: the vault sealed values but not addresses, and the budget/anchor keys (`personaId:epoch`) let an operator read the sibling table straight from the database. {cite: notes/reports/REPORT-Z1.md > "Fixed in this pass (the second Gate 4 iteration)"}
- The verifier never re-derived scope/message from (persona, gate, epoch, root), so a proof for persona A could be recorded as belonging to persona B — the project's own live test had enshrined the hole. {cite: notes/reports/REPORT-Z1.md > "Fixed in this pass (the second Gate 4 iteration)"}
- A closing sweep failed because the validator process silently vanished mid-run with no crash log; the cause was never established, so the validator was made to log its own exit/signal/uncaught-error and run under a restart supervisor. {cite: notes/reports/REPORT-Z1.md > "Closing sweeps"}
- A later closing-sweep failure traced to a legacy (non-ZK) crosspost route that never adopted the repo's own retry-adapter-reads rule, so a 2%-by-design mock failure blanked its price panel. {cite: notes/reports/REPORT-Z1.md > "Closing sweeps"}
- Bench (i7-14700F, node 24): cold proof 549 ms including artifact load, warm 232–307 ms (median 287 ms), verify 12 ms, proof 635 bytes at depth 20 with a 513-member group; mobile timing is explicitly unmeasured-extrapolated. {cite: notes/reports/REPORT-Z1.md > "GATE 0 — BUILT + CLOSED. accept-z0 11/11 (first run, ARMED)"}
- Twenty-nine attack attempts across three adversarial reports found nothing that broke through the proof layer itself — nullifier collision, history forking, leaf-index leakage and others all held. {cite: notes/reports/REPORT-Z1.md > "What the reviews could not break (their own lists, kept for scope)"}

## Judgment calls

- Message binding's challenge is epoch-bound and derived locally rather than validator-issued, because asking the validator for a challenge is itself an "I am about to prove" signal it could correlate. {cite: notes/reports/REPORT-Z1.md > "Judgment calls (logged, not asked)"}
- BigInt literals were avoided in `lib/zk` rather than bumping the project's `es2017` build target mid-crypto-pass. {cite: notes/reports/REPORT-Z1.md > "Judgment calls (logged, not asked)"}
- The validator now holds one Ed25519 signing key for its own signed statements (placements, history); its trust statement changes from "holds no private key" to "holds one key that attests its own statements," never touching user material. {cite: notes/reports/REPORT-Z1.md > "Judgment calls (logged, not asked)"}
- OHTTP was built on `@hpke/core`, the only maintained JS HPKE library, despite it not being formally audited — recorded as assumption A-HPKE-AUDIT rather than blocking the gate. {cite: notes/reports/REPORT-Z1.md > "Judgment calls (logged, not asked)"}
- The prompt says to stop the gate if ceremony hashes cannot be verified against a published source; since they verified against the ceremony's own outputs and a third party's attestation, the gate proceeded with the one unmechanizable step (a full `snarkjs zkey verify`) written as assumption A-ZKEY-VERIFY rather than a guarantee. {cite: notes/reports/REPORT-Z1.md > "What the ceremony check established (and what it could not)"}
- Cohort rotation between epochs was accepted as bounded, not closed: the fix refuses to prove into a cohort more than 20% churned from the last one, rather than requiring a placement circuit this pass didn't build. {cite: notes/reports/REPORT-Z1.md > "Fixed in this pass (the second Gate 4 iteration)"}

- A-REVOCATION-NOT-BUILT: revocation via epoch re-issuance, the pass's call option, was not exercised. {cite: notes/reports/REPORT-Z1.md > "Closure, stated exactly"}
- A-PREPARE-BURST: the eligibility-preparation burst is an identified beacon at the moment of proving, cheap to fix but not built here because the iteration budget went to the rebuttal. {cite: notes/reports/REPORT-Z1.md > "Step 2 — fork continuity (and the end of the plaintext attribution index)"}
- A-COHORT-ROTATION: cohort rotation between epochs can still isolate a root over roughly 28 epochs at 20% churn for a 500-leaf cohort; closing it fully needs the placement circuit, not a tighter churn knob. {cite: notes/reports/REPORT-Z1.md > "Fixed in this pass (the second Gate 4 iteration)"}
- A-PERSONA-ROOT-BINDING: nothing binds persona to the leaf that proved except the prover's own `isOwnPersona` check — fork continuity (this persona was forked from that one, by the same root) is exactly this relation, and is Step 2's job. {cite: notes/reports/REPORT-Z1.md > "WHAT THE NEXT STEPS NEED — written from what this pass actually built"}
- The persona↔root relation is still the operator's table (`personas.root_id`); "hidden at the proof layer" is the whole claim only for the one gate this pass built (For You discovery), not for every reputation read. {cite: notes/reports/REPORT-Z1.md > "Step 2 — fork continuity (and the end of the plaintext attribution index)"}
- The attribution index (`castHash→personaId`) is persona-signed but not yet root-blind — it must not sit beside a `personaId→rootId` row, which depends on the same Step 2 work. {cite: notes/reports/REPORT-Z1.md > "Step 2 — fork continuity (and the end of the plaintext attribution index)"}
- Step 4 (attestations) still needs an issuance table and issuer key, a second claim kind, expiry via epoch re-issuance, and a re-decided proof-history budget default once two claim kinds are live. {cite: notes/reports/REPORT-Z1.md > "Step 4 — attestations (`attest:<issuer>` trees)"}
- Assumptions stood without a fix in this pass include A-VERIFIER-MONOCULTURE (one snarkjs implementation verifies both sides), A-SINGLE-TENANT-REGISTRATION, A-HOST-INTEGRITY, A-HISTORY-COMMITS-TO-THE-PAST, A-DECORRELATION-IS-SCHEDULER-LEVEL, A-RELAY-PASSIVE-JOIN, A-GATEWAY-KEY-ROTATION, A-PRESENCE-LOG, A-MEMBERS-PUBLIC, A-DEV-SURFACE, and A-ESCROW-BLAST-RADIUS. {cite: notes/reports/REPORT-Z1.md > "Stood as ASSUMPTIONS (no fix possible in this pass; each is a line in SECURITY-POSTURE.md §3)"}
- The single silent validator death during the first closing-sweep attempt was never root-caused; it is recorded as an unexplained infrastructure blemish rather than rounded away. {cite: notes/reports/REPORT-Z1.md > "Closing sweeps"}
