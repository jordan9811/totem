## What it found

- A silent fail-open in mode filtering: `buildFeed` resolved a mode's `ruleIds` and skipped any it could not resolve, so a Work or Event Safe Space user was served an unfiltered feed with no indication anything was wrong; visible in a stability run as `outsideClusters=18` with `unfollowed=0`. It now throws and surfaces the feed error state instead. {cite: notes/reports/REPORT-G.md > "What the instability exposed in the product"}
- Hydration could drop preset rules because the `rules` namespace loader replaced the whole map, discarding presets already seeded in-process by `ensurePresetRules()`; it now merges, with persisted entries winning only for the ids they define. {cite: notes/reports/REPORT-G.md > "What the instability exposed in the product"}
- Persistence made every read a write: `mode.list`/`getActive` are marked as mutations because they seed presets on first call, so every feed build was PUT-ing whole namespaces to the validator over HTTP; `persistNs` now dirty-checks against the last flushed payload and skips identical writes. {cite: notes/reports/REPORT-G.md > "What the instability exposed in the product"}
- The suites were reporting infrastructure failures as safety violations — a 503 that never reached the handler was read as "sensitive claim accepted without consent," and a failed graph-clearing setup step was read as "ads shown to a viewer whose graph matches nothing." {cite: notes/reports/REPORT-G.md > "What the instability exposed in the tests"}
- A false alarm about a fail-open is its own kind of dangerous, because it burns the credibility of the check. {cite: notes/reports/REPORT-G.md > "What the instability exposed in the tests"}
- Attempt 1 (one long-lived dev server): runs 1-2 green, runs 3-4 failed with `POST /api/dev` returning HTTP 500 (`TypeError: Cannot read properties of null (reading 'useContext')`) from inside Next's own dev runtime. {cite: notes/reports/REPORT-G.md > "Stability across consecutive runs — the most instructive part of the pass"}
- Attempt 2 (`scripts/stability.sh`, fresh dev server per run): 0/4 runs fully green, dominated by `ECONNREFUSED ::1:3000` mid-run plus repeated `EINVAL readlink` on `.next/server/pages-manifest.json` at startup. {cite: notes/reports/REPORT-G.md > "Stability across consecutive runs — the most instructive part of the pass"}
- A mitigation tried and reverted: junctioning `.next` to `C:\layers-next` via `mklink /J` moved build output off OneDrive but broke Node module resolution (webpack-emitted requires could not walk up to `node_modules`), making stability total failure; the junction was removed. {cite: notes/reports/REPORT-G.md > "Stability across consecutive runs — the most instructive part of the pass"}
- Bug found in Gate 1: the Wave 4 seed block initially ran after `posts.json` was written, so channel posts existed in memory but never reached disk, failing criterion 1 with "no seeded invite-channel posts"; moved above the file writes. {cite: notes/reports/REPORT-G.md > "GATE 1 — Wave 4: Social Surfaces — CLOSED (5/5)"}

- Bug in Gate 3: a stale-count race in the audience estimator — two rapid audience changes could return out of order under 200-1500ms mock latency, letting a stale count overwrite a fresh one; fixed with a sequence guard. {cite: notes/reports/REPORT-G.md > "GATE 3 — Wave 6: Market Layer — CLOSED (6/6)"}

## Judgment calls

- `adapter_state` is a namespaced document table, not per-entity tables — the adapter owns the shape and the validator owns durability, since purpose-built tables would be premature for adapters whose real backend does not exist yet. {cite: notes/reports/REPORT-G.md > "Judgment calls (all gates)"}
- Gate 1's failure mode was pre-empted, not awaited: the spec said to unify timeline injection "if you see even one collision," and five injectors writing into one array was judged a collision waiting to happen. {cite: notes/reports/REPORT-G.md > "Judgment calls (all gates)"}
- The controllable clock was built in Gate 1, not retrofitted in Gate 3, because room liveness needed it first and the spec's "retrofit at the first flake" instruction was judged to apply equally to room scripts. {cite: notes/reports/REPORT-G.md > "Judgment calls (all gates)"}
- `graph.claim` extends `RuleField` rather than living in a parallel audience-predicate type, which is what makes "the audience builder IS the rules engine UI" literally true. {cite: notes/reports/REPORT-G.md > "Judgment calls (all gates)"}
- Test harnesses retry navigation because a Next dev server aborts navigations while compiling a route (`ERR_ABORTED`), which is infrastructure noise; a flaky harness would make the 4x-consecutive requirement meaningless. {cite: notes/reports/REPORT-G.md > "Judgment calls (all gates)"}
- `gate0.mjs` waits 300s for servers, not 90s, because cold start plus first compile on the OneDrive-backed working directory regularly exceeds 90s. {cite: notes/reports/REPORT-G.md > "Judgment calls (all gates)"}

## Assumptions and open items

- For day-to-day development in a synced folder, expect `next dev` to need an occasional restart under sustained automated load. {cite: notes/reports/REPORT-G.md > "Stability across consecutive runs — the most instructive part of the pass"}
- Mock state process-lifetime gap from the prior pass is CLOSED (Gate 0) — persisted and restart-tested including market state. {cite: notes/reports/REPORT-G.md > "Known gaps — dispositions"}
- `GraphAdapter` is the top-priority adapter for the real track: `claimsForMatching` is the privacy boundary for the whole ad system, and the real version must enforce per-category consent somewhere the client cannot bypass, keeping the "sensitive excluded on error" behaviour that `sensitiveIncluded: false` currently signals. {cite: notes/reports/REPORT-G.md > "Adapter interfaces the real track must implement next"}
- `MarketAdapter`'s `audienceSize` + `kFloor` are the k-anonymity guarantee; a real implementation needs a differentially-private audience estimate since an exact count is itself a disclosure channel, and `measurement` must keep returning aggregates that structurally cannot carry identifiers. {cite: notes/reports/REPORT-G.md > "Adapter interfaces the real track must implement next"}
- `SettleAdapter` currently records events on its own authority; real settlement needs actual escrow custody and an auditable ledger, preserving the `intent_award`/`intent_refund` split. {cite: notes/reports/REPORT-G.md > "Adapter interfaces the real track must implement next"}
- `SpaceAdapter`'s `isMember` and `canViewFolder` are the two fail-closed gates; a real implementation must make membership unforgeable client-side, since today the client is trusted because the mock is the source of truth. {cite: notes/reports/REPORT-G.md > "Adapter interfaces the real track must implement next"}
- `DisclosureAdapter` (from Waves 1-3) is still the phase-2 ZK target: `canViewLinkage` is a server-side boolean over a server-visible mapping. {cite: notes/reports/REPORT-G.md > "Adapter interfaces the real track must implement next"}
- `ModeAdapter` and `RulesAdapter` need no cryptography — rules are already evaluated client-side by real logic, which is the correct long-term shape. {cite: notes/reports/REPORT-G.md > "Adapter interfaces the real track must implement next"}
