- **[SHIPPED]** Gate 1: a full persona × mode matrix — mode-swipe without a persona switch, mode-forces-persona pinning, persona-default-mode on explicit switch, and a "more specific wins" session-scoped override that beats both. {cite: notes/reports/REPORT-UX.md > "GATE 1 — Persona × mode matrix, act-as-any-persona — CLOSED (13/13)"}
- **[SHIPPED]** Time/context auto-switch reuses the existing rules evaluator verbatim, off by default, checked lazily at the top of `buildFeed`. {cite: notes/reports/REPORT-UX.md > "The two binding directions"}
- **[SHIPPED]** Act-as-any-persona: server-side allowlist validation identical to real persona-switching, a dedicated seeded-system picker route kept separate from the phase-1 identity context, and reply/quote/recast logged to the acting persona with a `viaActAs` marker when it differs. {cite: notes/reports/REPORT-UX.md > "Act-as-any-persona"}
- **[SHIPPED]** Gate 2: timeline refresh undo via a client-side, depth-capped sessionStorage stack keyed per (persona, mode), restoring both the card set and the exact scroll position. {cite: notes/reports/REPORT-UX.md > "GATE 2 — Timeline refresh undo — CLOSED (8/8)"}
- **[SHIPPED]** Gate 3: selective bookmark/thread resolution integrated into the existing readwise chunking/populator via a minimal synthetic `SeedPost`, with zero changes to the chunker, loop, or card renderer. {cite: notes/reports/REPORT-UX.md > "GATE 3 — Selective bookmark / thread resolution — CLOSED (9/9)"}
- **[SHIPPED]** Cold-resolution state survives restart via a replay-hook/purge-hook pair mirroring the existing forked-persona pattern, proven by a real kill-and-restart cycle. {cite: notes/reports/REPORT-UX.md > "GATE 3 — Selective bookmark / thread resolution — CLOSED (9/9)"}
- **[SHIPPED]** Resolution batches are atomic and idempotent: one cap check over the whole batch before any item is marked resolved, and an empty pending set short-circuits before the ledger is touched at all. {cite: notes/reports/REPORT-UX.md > "GATE 3 — Selective bookmark / thread resolution — CLOSED (9/9)"}
- **[SHIPPED]** Gate 4: data backpack + Ad Match Score, reusing Wave 5's existing import mechanism — three of four source types needed zero new import-flow code. {cite: notes/reports/REPORT-UX.md > "GATE 4 — Data backpack + Ad Match Score — CLOSED (7/7)"}

- **[SHIPPED-FIXTURE]** Call Option A, X alt linking: opened and closed 9/9, fixture-only — a disclaimer gate, a daily cap of 3, and a randomized synchronous delay always in [3000, 12000)ms. {cite: notes/reports/REPORT-UX.md > "CALL OPTION A — X alt linking — OPENED, CLOSED (9/9)"}

## What it found

- `isOwn` on the profile page was computed from a fixed root-family membership check that ignored View-As entirely, incorrectly hiding follow/block/resurface controls from an acting persona that should see them — UI clutter, not a leak, since the API layer keys correctly. {cite: notes/reports/REPORT-UX.md > "GATE 0 — Import behavior fix — CLOSED (6/6)"}
- `getCast` didn't resolve private-post hashes at all, so a reply targeting a visible private post 404'd unconditionally. {cite: notes/reports/REPORT-UX.md > "Bugs found and fixed en route"}
- A naive quote of a private post via a public persona would have leaked the private post's existence and content onto the public timeline; refused with the same 404 as "doesn't exist." {cite: notes/reports/REPORT-UX.md > "Bugs found and fixed en route"}
- The initial act-as picker selection could default to a persona not in the options list when View-As was active, producing dead initial state. {cite: notes/reports/REPORT-UX.md > "Bugs found and fixed en route"}
- `resetSeed` disarmed the forced-failure budget but not its two siblings (`failureRateOverride`, `latencyInjection`/`maxOutLatency`), leaving the synthetic failure rate elevated across suites in the same long-lived dev-server process. {cite: notes/reports/REPORT-UX.md > "HARNESS FIX (cross-cutting, found during Gate 1 regression)"}
- The refresh/undo control sat at a non-sticky top-of-timeline position, so a user scrolled deep into their timeline — the exact scenario the feature exists for — would have to scroll back up to reach it. {cite: notes/reports/REPORT-UX.md > "GATE 2 — Timeline refresh undo — CLOSED (8/8)"}
- Several pre-existing suites accepted the first 2xx response from a multi-adapter fan-out route without checking content-completeness, surfacing as spurious failures unrelated to the feature under test. {cite: notes/reports/REPORT-UX.md > "HARNESS OBSERVATION (not chased further mid-pass)"}
- A hand-written seed item and a placeholder generator both produced the id `cold_bf_longform_0`, so 40 resolved items quietly produced only 39 unique schedules — caught by an exact-count assertion, not inspection. {cite: notes/reports/REPORT-UX.md > "GATE 3 — Selective bookmark / thread resolution — CLOSED (9/9)"}
- `computeScore`'s consent check looped over three sensitive categories sequentially, each independently retriable at up to 1500ms, adding up to 4.5s to every score read; fixed with `Promise.all`. {cite: notes/reports/REPORT-UX.md > "GATE 4 — Data backpack + Ad Match Score — CLOSED (7/7)"}
- A real architectural pivot: the natural reading of Call Option A (link two of the user's own personas) doesn't fit the fixture's viewer roster, since the second persona is private and private personas are correctly barred from carrying external attestations. {cite: notes/reports/REPORT-UX.md > "CALL OPTION A — X alt linking — OPENED, CLOSED (9/9)"}
- Duplicate block events: a bare, un-retried adapter read (`blockedFor()`) hit the mocks' natural 2% synthetic failure after the block and its log entry had already landed, so a client retry minted a second event with a new random id. {cite: notes/reports/REPORT-UX.md > "PRODUCT BUG FOUND BY THE FINAL SWEEPS — duplicate block events"}
- Event ids are random, so the relationship event log's idempotency holds for in-process retries but not client-level HTTP retries — the real fix, caller-supplied idempotency keys, was deferred to a dedicated pass. {cite: notes/reports/REPORT-UX.md > "PRODUCT BUG FOUND BY THE FINAL SWEEPS — duplicate block events"}
- A twice-logged harness observation (the content-aware-retry gap) was caught for real at final sweep verification across three suites (accept-b2, accept-a3, accept-a4), all test bugs rather than product bugs. {cite: notes/reports/REPORT-UX.md > "HARNESS FIX (final) — content-aware retry, the observation finally closed"}

## Judgment calls

- The "long-press hexagon menu" the prompt described as already prototyped doesn't exist anywhere in the codebase; built as an "Act as…" item in the existing cast kebab menu instead, since long-press has no clean desktop equivalent. {cite: notes/reports/REPORT-UX.md > "GATE 1 — Persona × mode matrix, act-as-any-persona — CLOSED (13/13)"}
- On an exhausted retry, the block-list route now returns 200 with `blockedPersonaIds: null, listUnavailable: true` — deliberately `null` and flagged, never an empty array, because an empty array would read as "nobody is blocked." {cite: notes/reports/REPORT-UX.md > "PRODUCT BUG FOUND BY THE FINAL SWEEPS — duplicate block events"}
- `/api/follow`'s structurally similar failure mode was audited and deliberately left alone, because making it best-effort would be a regression, not a fix. {cite: notes/reports/REPORT-UX.md > "PRODUCT BUG FOUND BY THE FINAL SWEEPS — duplicate block events"}
- Cold-source fixture data lives on the seed viewer's primary persona only, matching every other X-interop fixture; nothing about the design is single-persona-only. {cite: notes/reports/REPORT-UX.md > "GATE 3 — Selective bookmark / thread resolution — CLOSED (9/9)"}
- No per-category anti-spam cap on the Ad Match Score, since a cap would interact awkwardly with the "breakdown sums to the score exactly" requirement and wasn't asked for. {cite: notes/reports/REPORT-UX.md > "GATE 4 — Data backpack + Ad Match Score — CLOSED (7/7)"}

## Verification result

- 4 consecutive clean sweeps: 239/239 passing checks, 0 failed suites, 0 infra, on every run; tsc strict clean; production build clean. {cite: notes/reports/REPORT-UX.md > "/VERIFY — FINAL RESULTS"}
- Restart-survival 25/25, including bindings, resolved bookmarks, and backpack claims + score; the undo stack explicitly does NOT survive restart. {cite: notes/reports/REPORT-UX.md > "/VERIFY — FINAL RESULTS"}
- Root-leak clean across 46 payloads; ENABLE_X_WRITE unset throughout, live spend $0.00. {cite: notes/reports/REPORT-UX.md > "/VERIFY — FINAL RESULTS"}
- The 4-consecutive-sweep protocol paid for itself twice: a real duplicate-block-event bug and a real 4.5s scoring performance bug were both invisible to every isolated suite run. {cite: notes/reports/REPORT-UX.md > "What the sweeps actually earned"}

## Assumptions and open items

- Extension-connected alt linking is out of scope; only OAuth exists anywhere in this codebase. {cite: notes/reports/REPORT-UX.md > "KNOWN-BROKEN"}
- A per-category anti-spam cap on the score is worth a follow-up if richness scoring becomes a real incentive surface rather than a preview. {cite: notes/reports/REPORT-UX.md > "GATE 4 — Data backpack + Ad Match Score — CLOSED (7/7)"}
- Alt-link records (`AltLinkAttempt`, `altXHandles`) are named as the single most sensitive record the product has ever created, placed at the very top of what the vault must hold. {cite: notes/reports/REPORT-UX.md > "WHAT THE VAULT MUST HOLD"}
- Caller-supplied idempotency keys for `logEdgeEvent` call sites are deferred to a dedicated pass, since changing dedup semantics during final verification risked collapsing legitimately distinct events. {cite: notes/reports/REPORT-UX.md > "PRODUCT BUG FOUND BY THE FINAL SWEEPS — duplicate block events"}
- A dedicated harness-hardening pass is worth doing to audit every accept-*/restart-survival check that reads a multi-adapter fan-out response for content-aware retry, not just status-code retry. {cite: notes/reports/REPORT-UX.md > "HARNESS OBSERVATION (not chased further mid-pass)"}
