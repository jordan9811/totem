## The reset contract does not cover validator TABLES (post-deploy pass, /verify)

`POST /api/dev {action:"resetSeed"}` clears `adapter_state` and every sealed
cache, and the suites lean on it as "the rig is back to default". It does not
clear validator TABLES. Over roughly fifteen closing sweeps the block-testing
suites accumulated 97 rows in `blocks_v2`, which is enough to block nearly
every author in the small phase-1 fixture cast set — and the classic home feed
then rendered empty, with no error anywhere, until the rows were purged by
hand.

Nothing about this is specific to blocks: any validator table a suite writes
and the reset does not clear will drift the same way. The visible symptom was
a settle guard refusing to launch, which is the good case; the bad case is a
suite passing against a rig that no longer resembles a fresh one.
